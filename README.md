# qmk-config-Keyball39

Keyball39（Charybdis ベース / MochuKeeb フォーク）の個人設定リポジトリ。
config.h / keymap.c を push すると GitHub Actions がファームウェア（UF2）をビルドする。

- 物理: Keyball39（右手トラックボール）、MCU = **v2/splinky (RP2040)** ×2
- ファーム: Vial 対応 QMK（Charybdis 系）
- ホスト: MacBook Pro M4 Max / Karabiner-Elements（JIS 仮想キーボード）
- スイッチ: **HRM＋親指キー＝タクタイル、その他＝リニア**の混載

---

## 現在のレイアウト要点

| 部位 | 割当 |
|---|---|
| ホームロウ | A=Alt S=GUI D=Ctrl F=Shift / J=Shift K=Ctrl L=GUI '=Alt |
| G / H | **RGUI_T（右⌘）** — rcmd でのアプリ切替用 |
| 左親指 L1/L2 | **英数 / かな**（LANG2/LANG1） |
| 左親指 L3 | タップ=Esc、ホールド=GAME レイヤ |
| マウス | **MO ホールド中のみ**（オートマウスレイヤは全廃） |
| レイヤ3 左親指 | QK_BOOT / EE_CLR / T_SAVE / TInfo（管理キー集約） |

設計方針:

- **オートマウスレイヤを使わない**。ボールに触れただけでレイヤが変わる誤爆
  （特に日本語 IME の変換中確定）を嫌い、ホールド中だけマウスにする
- **シングルタップで状態が固定されるキー（TG など）をベースレイヤに置かない**
- GAME レイヤ（HRM なし素 QWERTY）へは2段階操作でのみ入る

## 運用メモ

### ビルドと書き込み

1. config.h / keymap.c を編集して push → Actions が UF2 を生成
2. artifact を DL し、**両半身に**書き込む
   - bootloader: レイヤ3 左親指1番目（QK_BOOT）または基板リセット2回押し
   - `RPI-RP2` ボリュームに UF2 をドラッグ
   - **左半身は USB を直結して焼く**（QK_BOOT は常に master 側を再起動するため）
3. 書き込み前に必ず Vial → File → Save current layout で .vil を退避

### EE_CLR の注意（重要）

`EE_CLR` は **Vial で上書きしたキーマップ・コンボ・ユーザー設定をすべて消す**。
実行後は最新の .vil バックアップから File → Load saved layout で復元すること。

> 2026-10 の教訓: スイッチ修理中に EEPROM が初期化され、**古い .vil から復元して
> しまったため LANG キー・右⌘・TInfo の3改善を 20 日間失ったまま気づかなかった**。
> バックアップは日付付きで世代管理し、復元には必ず最新を使う。

## 事件簿

### ① ポインタ遅延・カクつき事件（2026-09〜10）

**症状**: Mac を放置した後に使うとポインタがカクつく。再起動すると治る（ように見えた）。

**容疑者リスト（すべて実測で棄却）**:
システム負荷 / Time Machine / macOS の USB・HID 層（ReportInterval 1 kHz で正常）/
Karabiner のルール / センサ・ボールの汚れ / **マグネット USB コネクタ（両端撤去しても不変）**/
半身間ケーブル / 外部モニタ / WindowServer の肥大（RSS 1.1 GB まで育っていたが無関係）/
Steam（GCMouse として Keyball を掴んでいたが無関係）/ USB ポート（左右両方で再現）

**真犯人**: **Karabiner-Elements 16.1.0 の core_service デーモンの経時劣化**。

```
sudo launchctl kickstart -k system/org.pqrs.service.daemon.Karabiner-Core-Service
```

を打った瞬間に完治したことで確定。16.2.0 で CGEventTap のメモリリーク、16.3.0 で
スリープ復帰後の無応答が上流修正されており、**16.3.0 へ更新して恒久解決**。

Keyball だけがカクつき内蔵トラックパッドが無事だった理由: Karabiner は外付け
キーボードを grab するが、内蔵トラックパッドのポインティングは掴まないため。

### ② ボールとキーが同時に使えない事件（2026-09-30）

**症状**: ボールを動かした直後にキーを打つと変な文字が出る／何も出ない。常時再現。

**真犯人**: config.h の `CHARYBDIS_AUTO_POINTER_LAYER_TRIGGER_ENABLE`。

QMK 側のオートマウスレイヤ（`POINTING_DEVICE_AUTO_MOUSE_ENABLE` / AML_TO）を
オフにしていても、**Charybdis 独自の自動ポインタレイヤ機構が別に存在**し、
こちらが生きていた。ボールを動かすと自動でレイヤ1に入り、打鍵がスクショ系
ショートカットや F キーに化けていた。1 行コメントアウトで解決。

あわせて `OLED_UPDATE_INTERVAL 100` を導入（OLED の全面再描画がメインループを
圧迫していたため）。

### ③ SW17 沈黙事件（2026-10 中旬）

**症状**: 左手最下段・薬指位置のキー（現かなキー）が反応しない。はんだし直すと
一時復活、また死ぬ、を繰り返す。

**捜査**: 回路図で経路を特定（`COL1 → SW17 → D20 → ROW3`）。Vial の Matrix tester で
COL1/ROW3 本線の健全を確認し、容疑を SW17 の枝に限定。「D20 を叩くと途切れる」
証言で **ダイオード D20 を逮捕・交換するも再発（冤罪）**。死んだ瞬間にスイッチ両
パッドをピンセット短絡する T1 テストで判定 → **真犯人はスイッチ内部の接点疲労**。
スイッチ交換で完治。

後日談: このキーが GAME トグルだった時代の「たまに勝手に GAME モードに入る」
誤爆は、指の掠りではなく**死にかけ接点のチャタリング**だった可能性が高い。

## 教訓集

1. **症状は1つでも原因は複数ある。** 今回は「ファーム設定」「ホストのバグ」
   「ハード故障」「OS の加速設定」の4つが合流して「ポインタがおかしい」に見えていた
2. **「再起動で治る」という記憶を証拠にしない。** 実測したら再起動なしで
   治ったり悪化したりしていた。思い込みが物理層の候補を不当に棄却させた
3. **内蔵トラックパッドとの比較が最強の切り分け。** デバイス固有かホスト全体かが
   10 秒で割れる
4. **同名の機能が2系統ある罠。** QMK のオートマウスと Charybdis の自動ポインタ
   レイヤは別物。片方を切っても片方が生きる
5. **USB 切断は復帰までの時間で分類する。** 数秒で復帰=接触不良、数分以上=スリープ
6. **間欠故障は「死んでいる瞬間」に測る。** 生き返ってから測っても何も分からない
7. **修理の前後で .vil を書き出す。** EEPROM は思わぬタイミングで初期化される
8. **入力系ソフトはまずバージョンと changelog を確認。** 2 つ後ろの版で直っていた
